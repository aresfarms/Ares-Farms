# Property Report preparation — September 29, 2026

The $49 Property Report remains required for launch. Nationwide coverage across property types remains the goal; prioritize demonstrable evidence coverage rather than silently excluding states. This change is a candidate for private testing, not launch acceptance.

## What changed

From a property analysis, select **Save this property and prepare its report**. Save the property explicitly to start the existing private queue. The preparation page shows the persisted status and the evidence still needed, and supports reopening with the reference and private recovery token. Tokens are kept out of URLs; separate properties retain separate browser credentials. No payment is created by saving or checking status.

The analysis worker now captures the same governed property facts used by the report, with its capture date, classification, runtime trace and replay reference. Public records may establish a starting fact without proving suitability for a proposed business. The 19-domain checklist distinguishes captured research from missing evidence; captured research is never self-promoted to an approved economic package. The current-price policy applies here too: an old listing or assessment does not become a purchase price.

Completed evidence is read in its actual persisted package/assessment format. Readiness and checkout reassess freshness and property identity. The finished PDF and storage bytes must still pass verification before a payment session can open. Checkout accepts only a supported candidate selector or no preference; arbitrary customer text cannot enter automated ranking. Selecting an existing candidate does not create a duplicate third use. The report's findings and conditions replace generic free-screen statements that incorrectly called a completed budget missing.

The private worker now handles at most three properties per stage per scheduled run to allow time for broader source checks within the existing job timeout. Throughput, recovery after a killed job, and production source access still need private runtime acceptance.

## What remains

Ordinary intake still does not automatically assemble reviewed property-specific demand, competition, operating budgets, capital costs, financing and use-feasibility packages. The preparation page and captured records are the connection to that work, not a substitute for it. No source license or review approval is inferred from a successful public lookup.

The existing economic compiler still requires three complete candidate packages. The September 4 amendment permits fewer genuinely supported uses and prohibits inventing a third. A governed representation of evaluated exclusions, with evidence for every material conclusion, must resolve that policy mismatch before launch; do not simply lower the count or fabricate an alternative.

Representative real reports, actual Stripe test-mode/storage acceptance, security warning disposition, commercial/support terms, independent signoffs and public HTTPS/domain acceptance remain outstanding. Sales, deployed application revisions and DNS are unchanged.

## Verification

Contract tests cover actual stored package wrappers, wrong-property rejection, stale sources, capture versus review, supported choices, missing-budget text, separate saved credentials and expired recovery. The isolated PostgreSQL acceptance suite additionally exercises save, evidence-gap persistence, authorized reopen, wrong-token denial and completion through the real database schema. Provider/payment inputs in this suite remain synthetic.

A local production build and mobile browser exercise cover saving, reload without duplicate intake, token recovery, explicit access errors, no horizontal overflow and no browser errors using synthetic API responses. These checks do not establish successful source collection in the deployed worker or acceptance of a real $49 report.
