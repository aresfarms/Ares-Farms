# Doctrine: Authoritative Map Asset Ingestion V1

**ID:** AUTHORITATIVE_MAP_ASSET_INGESTION_V1  
**Version:** 1.0.0  
**Effective:** 2026-06-05  
**Owner:** Platform Governance  
**Volume Reference:** Ares Volume III §Map Asset Governance

---

## Governing Principle

No fake, hand-drawn, or memory-based U.S. geographic silhouette may appear on any public-facing surface of the Furlong platform.

Any map or geographic visual that claims to represent the United States must be derived from authoritative government data sources, cached locally before deployment, and verified by the `verify:map-assets` gate before any release.

---

## Approved Data Sources

Sources are tiered by authority. The highest available tier must be used.

| Tier | ID | Source | License |
|------|-----|--------|---------|
| Tier 1 (Federal) | `census_tiger_rest` | U.S. Census Bureau TIGER Web Services | Public domain — U.S. federal government |
| Tier 1 (Federal) | `census_cartographic` | U.S. Census Bureau Cartographic Boundary Files | Public domain — U.S. federal government |
| Tier 3 (Public Domain) | `natural_earth` | Natural Earth | Public domain — volunteer cartographers |

Any source not listed in `src/lib/maps/mapSourceRegistry.ts` is **not approved** for use.

---

## Prohibited Practices

The following are absolutely prohibited:

1. **Live fetch of map data during visitor page load.** Map boundaries must be cached locally before deployment. A visitor's page load must not depend on Census Bureau uptime.

2. **Fake geographic silhouettes.** No SVG path, image, or canvas element may represent a U.S. map outline that was not derived from an approved source.

3. **Memory-based outlines.** No implementation may encode U.S. state or county boundaries as hardcoded coordinate arrays in application source code, unless those coordinates were generated by the ingestion pipeline and documented as such.

4. **Geolocation.** No map or geographic visual on any public surface may use the visitor's device location.

5. **Exact addresses.** No map may display or reference specific property addresses.

6. **Third-party runtime dependency for homepage rendering.** The homepage map must render from local assets only. If a third-party map tile service is down, the homepage must still function.

---

## Required Asset Structure

All map assets must be stored in `public/maps/` with the following files:

| File | Contents |
|------|---------|
| `us-states.geojson` | GeoJSON FeatureCollection of U.S. state boundaries (≥50 features) |
| `us-counties.geojson` | GeoJSON FeatureCollection of featured county boundaries (≥1 feature) |
| `us-map-metadata.json` | Provenance metadata (see required fields below) |

### Required Metadata Fields

Every `us-map-metadata.json` must contain all of the following:

- `source_name` — Full name of the data source
- `source_url` — URL from which data was fetched
- `source_authority_tier` — One of: `tier-1-federal`, `tier-2-federal`, `tier-3-public-domain`
- `source_version_or_year` — Dataset vintage (e.g. "2023")
- `fetched_at` — ISO 8601 timestamp of ingestion
- `content_hash` — SHA-256 hash of all asset content (combined)
- `license_or_public_domain_note` — Human-readable license or public domain declaration
- `simplification_level` — Description of geometry simplification applied
- `replay_ref` — Unique replay reference for this ingestion run
- `generated_by` — Script name and version that produced the assets
- `generated_at` — ISO 8601 timestamp of asset generation

## Ingestion Protocol

### When to Run Ingestion

- Before every initial deployment
- When map assets are missing from `public/maps/`
- When the Census Bureau releases updated boundary files (annually, around Q1)
- When a featured exploration story references a new state or county

### How to Run Ingestion

```bash
npm run ingest:map-assets
npm run verify:map-assets
```

Both commands must succeed before the application may be deployed.

### Ingestion Authority

Ingestion may only fetch from approved sources defined in `src/lib/maps/mapSourceRegistry.ts`. The ingestion script must compute a SHA-256 content hash of each output file and record it in the metadata.

---

## Verification Gate

`npm run verify:map-assets` is a **deployment gate**. It must pass before any release.

The verifier fails if any of the following are true:

- `us-states.geojson` is missing
- `us-counties.geojson` is missing
- `us-map-metadata.json` is missing
- State feature count is below 50
- County feature count is below 1
- Any feature has null or missing geometry
- A featured exploration story references a state not present in the states asset
- A featured exploration story references a county not present in the counties asset
- Any required metadata field is missing
- `content_hash` is missing or malformed
- `source_authority_tier` is missing
- `license_or_public_domain_note` is missing
- The `LivingOpportunityMap` component contains banned fake-map markers
- The `LivingOpportunityMap` component does not reference real map assets

### What Passes (Fallback UI Does Not Override Gate)

The existence of a fallback UI ("Opportunity Network — Map asset temporarily unavailable") does not satisfy the verification gate. The gate verifies the assets themselves, not the UI state. A deploy with missing or invalid assets must fail even if the fallback UI would render.

---

## Fallback UI Requirements

If map assets are not available at component mount time (e.g., `fetch('/maps/us-states.geojson')` fails):

1. **Do not render** a fake U.S. silhouette or any geographic outline not derived from an approved source.
2. **Render** a professional abstract opportunity network visual.
3. **Label it** clearly: `Opportunity Network — Map asset temporarily unavailable.`
4. The label must be visible to the user without any hover or interaction.

The fallback is a degraded state, not an acceptable permanent state. If the fallback is visible in production, the ingestion pipeline must be re-run immediately.

---

## Featured Exploration Coordinates

Geographic coordinates used to position featured exploration markers on the map are:

- Real geographic centroids from U.S. Census TIGER data
- Illustrative only — they identify a county region, not a specific property or individual
- Must be within the county's actual boundaries
- Must not represent or imply a specific address

When adding a new featured exploration story, the operator must:

1. Verify the county name exactly matches a feature in `us-counties.geojson`
2. Add the county to `FEATURED_COUNTY_QUERIES` in `src/lib/maps/mapSourceRegistry.ts`
3. Re-run `npm run ingest:map-assets`
4. Re-run `npm run verify:map-assets`
5. Add `latLon` to the new story using the county centroid

---

## Privacy Requirements

The map must not:

- Use, infer, or display the visitor's location
- Use browser geolocation APIs
- Store or transmit any location data from the visitor
- Use language suggesting the map is personalized (e.g., "near you", "based on your location")

All featured explorations must carry the disclosure: "Illustrative example — not based on your location."

---

## Replay and Audit

Every ingestion run produces a `replay_ref` in the format `MAP_ASSET_INGESTION_YYYY-MM-DDTHH-MM-SS`. This reference:

- Is recorded in `us-map-metadata.json`
- Must be preserved in build records for any release that includes map assets
- Allows reconstruction of the exact ingestion run that produced the deployed assets
