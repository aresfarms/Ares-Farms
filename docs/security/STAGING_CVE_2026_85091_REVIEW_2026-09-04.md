## Finding

Google On-Demand Scanning reports one HIGH finding in each candidate image: CVE-2026-85091 in Debian 13 zlib `1:1.3.dfsg+really1.3.1-1` (CVSS 8.3). The pinned distroless Node 24 Debian 13 base is still the current distroless `latest` digest, so rebuilding against the current upstream distroless image does not remove the finding.

Debian's security tracker currently marks the trixie, forky and sid zlib packages vulnerable and lists the issue as unfixed. The vulnerable path concerns `gz_vacate()` after a non-blocking `gzwrite()` stall followed by `gzprintf()`/`gzvprintf()`.

## Compensating controls and reachability review

1. Repository search found no direct references to `gzprintf`, `gzvprintf`, `gzwrite`, or `gz_vacate` in `src/`, `scanner/`, or `public/`.
2. `npm run verify:dependency-security` reports zero production dependency advisories; this finding is in the base operating-system library, not the application npm dependency graph.
3. The core testing service remains behind Google IAP. Its Cloud Run invoker policy is limited to Caitlin Hudson, the IAP service agent, DAST, and governed source-refresh identities.
4. The scanner is not anonymously invokable: its Cloud Run invoker policy grants only the Furlong core runtime service account.
5. The migrator is a one-shot internal Cloud Run Job using the dedicated database-migrator service account and Secret Manager reference; it is not a public HTTP service.
6. Binary Authorization remains enforced. Candidate digests must be individually attested before staging use.
7. Stable staging traffic must remain on the existing revision while the candidate is first deployed at zero ordinary traffic under a testing tag.
8. Production cutover, public production exposure, live lender delivery and other production/live-action gates remain blocked.

## Decision

CVE-2026-85091 is **conditionally accepted for the founder-only staging evaluation lane only** because no patched Debian trixie/distroless package is currently available and the vulnerable API path is not directly used by the application source. This is not a finding closure and must not be represented as zero-HIGH security posture.

The acceptance expires immediately when any of the following occurs:

- Debian or the pinned distroless base publishes a fix;
- evidence shows the vulnerable zlib API path is reachable in Furlong runtime behavior;
- staging access controls are broadened beyond the bounded testing lane; or
- the candidate is proposed for production/permanent promotion.

Before any permanent/production promotion, rebuild against a fixed base (or otherwise remediate), rescan, and require effective HIGH/CRITICAL = 0 unless a new production-specific security authority explicitly approves a separate exception.
